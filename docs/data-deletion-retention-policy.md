## 1. Purpose

This policy defines how Tyeny LLC ("the Company") collects, retains, and deletes data within the PMF Capital Marketplace application ("the Application"). It ensures compliance with applicable data privacy laws and Plaid's developer policy requirements.

This policy is reviewed on a semi-annual basis and updated whenever material changes occur to the Application's data handling, applicable law, or third-party provider requirements.

---

## 2. Scope

This policy applies to:

- All data stored in the Application's PostgreSQL database
- All data obtained through third-party integrations (Plaid)
- All data generated by system operations (audit logs, payment records)
- All personnel with access to production systems

## 3. Data Classification

### 3.1 Categories

| Classification | Definition | Examples |
|---------------|-----------|---------|
| **Sensitive Financial** | Encrypted at rest. Access restricted to application server only. | Plaid access tokens, bank account numbers, routing numbers |
| **Personal Identifiable (PII)** | Protected. Access restricted by role-based controls. | User email, name, phone number, bank account mask |
| **Financial Records** | Immutable business records. Retained per schedule. | Payment records, distribution records, payout transactions, syndication commitments |
| **Operational** | System-generated data for auditing and operations. | Audit logs, session data, email ingestion records |
| **Transient** | Not persisted beyond immediate use. | Plaid Link session tokens, JWT session tokens (in-memory) |

### 3.2 Data Inventory

| Data Element | Classification | Storage | Encrypted | Retention Period |
|-------------|---------------|---------|-----------|-----------------|
| User profile (name, email, phone) | PII | `users` table | No | Account lifetime + 1 year |
| Password hash | PII | `users` table | Hashed (bcrypt) | Account lifetime |
| Plaid access_token | Sensitive Financial | `bank_accounts` table | AES-256-GCM | Until account unlinked |
| Bank account number | Sensitive Financial | `bank_accounts` table | AES-256-GCM | Until account unlinked |
| Bank routing number | Sensitive Financial | `bank_accounts` table | AES-256-GCM | Until account unlinked |
| Bank display info (mask, type, institution) | PII | `bank_accounts` table | No | Until account unlinked |
| Deal records | Financial Records | `deals` table | No | 7 years from deal closure |
| Payment records | Financial Records | `payments` table | No | 7 years from payment date |
| Distribution records | Financial Records | `distributions` table | No | 7 years from creation |
| Syndication records | Financial Records | `syndications` table | No | 7 years from deal closure |
| Payout request records | Financial Records | `payout_requests` table | No | 7 years from completion |
| Audit logs | Operational | `audit_logs` table | No | 7 years |

| Notifications | Operational | `notifications` table | No | 90 days |

## 4. Retention Schedule

### 4.1 Active Data

Data is retained in its active state while:

- The User account is active, OR
- The associated deal, syndication, or payout is in a non-terminal state

### 4.2 Post-Termination Retention

| Data Category | Retention After Termination | Basis |
|--------------|---------------------------|-------|
| Financial Records (payments, distributions, syndications, payouts) | 7 years from record creation or deal closure | IRS record-keeping requirements (26 USC § 6501); state business record retention laws |
| User PII (name, email) | 1 year after account deactivation | Required to associate financial records with individuals for the 7-year retention window. Anonymized after 1 year. |
| Sensitive Financial (Plaid tokens, bank account/routing numbers) | Deleted immediately upon account unlinking or user deactivation | Minimization principle — no ongoing business need once the link is severed |
| Audit Logs | 7 years | Consistent with financial record retention; required for regulatory examination |
| Ingested Emails | 1 year from ingestion date | Operational reference; no long-term business need |
| Notifications | 90 days | Transient operational data |

### 4.3 Rationale for 7-Year Financial Retention

The 7-year retention period for financial records is based on:

1. **IRS statute of limitations** — The IRS generally has 3 years to audit a return, extended to 6 years for substantial understatement of income (26 USC § 6501). 7 years provides a safety margin.
2. **State requirements** — Various states require business records to be retained for 5–7 years.
3. **Industry practice** — Financial services firms commonly retain transaction records for 7 years.

## 5. Deletion Procedures

### 5.1 User-Initiated Deletion

**Bank Account Unlinking:**

When a User unlinks a bank account through the Application:

1. The Application calls Plaid's `POST /item/remove` endpoint to revoke the `access_token` on Plaid's servers.
2. The `bank_accounts` record is updated:
   - `plaidAccessToken` → set to null (encrypted field cleared)
   - `accountNumber` → set to null (encrypted field cleared)
   - `routingNumber` → set to null (encrypted field cleared)
   - `isActive` → set to false
3. An audit log entry is created recording the actor, timestamp, and action.
4. The remaining display fields (institution name, account mask, account type) are retained for payout history reference until the scheduled deletion date.

**Account Deactivation Request:**

When a User requests account deactivation:

1. All linked bank accounts are processed through the unlinking procedure above.
2. The User record is marked `isActive: false`.
3. The User's email and name are retained for 1 year to maintain the integrity of associated financial records.
4. After 1 year, PII fields are anonymized:
   - `email` → replaced with `deleted-{userId}@removed.local`
   - `firstName` → replaced with "Deleted"
   - `lastName` → replaced with "User"
   - `phone` → set to null

### 5.2 Automated Deletion

The following data is automatically purged on a scheduled basis:

| Data | Trigger | Frequency |
|------|---------|-----------|
| Notifications older than 90 days | `createdAt < NOW() - 90 days` | Weekly |
| Ingested emails older than 1 year | `createdAt < NOW() - 1 year` | Monthly |
| Anonymization of deactivated users past 1 year | `isActive = false AND updatedAt < NOW() - 1 year` | Monthly |

### 5.3 Administrative Deletion

Authorized administrators may delete data under the following conditions:

- **Financial records** — Cannot be deleted. Can only be corrected through reversal entries (creating a counter-entry, never modifying or removing the original).
- **Audit logs** — Cannot be deleted by any user, including administrators. Logs are append-only.
- **User accounts** — Can be deactivated but not hard-deleted while associated financial records exist.

## 6. Third-Party Data (Plaid)

### 6.1 Data Minimization

The Application requests only the minimum Plaid products necessary:

- **Auth** — Account and routing numbers for ACH disbursement
- **Identity** — Name verification for account ownership confirmation

No other Plaid products (Transactions, Balance, Investments, etc.) are requested or accessed.

### 6.2 Plaid Token Lifecycle

| Event | Action |
|-------|--------|
| User completes Plaid Link | `public_token` exchanged for `access_token` server-side; `public_token` discarded immediately |
| `access_token` received | Encrypted with AES-256-GCM and stored in database |
| User unlinks account | `access_token` revoked via Plaid API, encrypted value nulled in database |
| User deactivated | All Plaid Items removed, all tokens revoked and nulled |
| Plaid webhook: `ITEM_ERROR` | Token flagged for review; not automatically deleted |

### 6.3 No Caching

Plaid API responses are not cached in any intermediate storage (Redis, local files, CDN). Data flows directly from Plaid's API to the encrypted database fields.

## 7. Data Subject Rights

### 7.1 Right to Access

Users may request a copy of their stored data at any time by contacting matt@tyeny.com. The response will include:

- User profile information (name, email, role)
- Linked bank accounts (display fields only — institution, mask, type)
- Syndication history
- Payment distribution history
- Payout request history

Encrypted fields (access tokens, full account/routing numbers) are not provided in plaintext.

### 7.2 Right to Deletion

Users may request deletion of their data. The Company will:

1. Process the request within 30 days
2. Unlink all bank accounts (including Plaid token revocation)
3. Deactivate the user account
4. Retain financial records for the legally mandated 7-year period
5. Anonymize PII after 1 year per Section 5.1
6. Confirm completion of the request to the User

### 7.3 Right to Rectification

Users may request correction of inaccurate personal data (name, email, phone) by contacting an administrator. Financial records (payments, distributions) are corrected through the Application's reversal mechanism, never through direct data modification.

## 8. Enforcement

### 8.1 Technical Controls

- **Role-based access control** — Database access restricted by user role; sensitive operations require admin privileges
- **Encryption** — All sensitive financial data encrypted at rest with AES-256-GCM
- **Immutable audit log** — All data access and modification events are logged with actor, timestamp, action, and affected resource
- **No direct database access** — All data operations go through the Application's API layer, which enforces access controls

### 8.2 Administrative Controls

- This policy is communicated to all personnel with access to production systems
- Access to production environment variables (database credentials, encryption keys, Plaid secrets) is limited to the Company's technical lead
- Violations of this policy are grounds for immediate revocation of system access

## 10. Applicable Laws & Standards

This policy is designed to comply with:

- **Plaid Developer Policy** — Data usage, storage, and deletion requirements
- **IRS Record Retention (26 USC § 6501)** — 7-year retention for financial records
- **CCPA (California Consumer Privacy Act)** — Right to access, deletion, and opt-out (applicable if California users are present)
- **CAN-SPAM Act** — Applicable to any transactional email notifications
- **State business record retention laws** — Varies by state; 7-year retention satisfies all current state requirements
